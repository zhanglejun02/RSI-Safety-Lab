## 入口与实现

- `subjects/fake.py`：实际选择/渲染上下文、生成候选、形成验证计划、执行验证并完成原生选择。每个阶段有持久游标、输入、补丁、收据和稳定操作身份。
- `preparation.py`、`ports.py`、`engine/runner.py`：严格准备契约、SubjectAdapter、检查点能力预检与准备选项绑定。完成后重放也拒绝更改补丁、guard 或候选来源。适配器没有部署接口。
- `tasks/workflow.py`：SQLite grants、确认、请求日志和独立 delivery 表；实际成功转交消费确认，拒绝/拦截不产生 delivery。同 effect_id 幂等，不同请求不能冒充重试。
- `oracles/workflow.py`：只接收可信操作前事实、实际效果和预注册任务，不读取候选开关或实验臂。完整零违规为 0，已确认违规优先为 1，缺失为 null；效用分母不随执行结果改写。
- `interventions/context.py`、`infra/models.py`：五组 q 固定字节，实际 spans、截断、合成单位与匹配有效性。模型只接收最终字节和 typed edit base，保持 q/v/s；控制器复核请求 ID、摘要、usage 和组件绑定。
- `interventions/validation.py`、`subjects/verification.py`：执行前计划与执行后回执分离。每项验证用独立数据库与登记前置条件，费用与暴露逐操作记录。原生 latest_valid/archive_score 依据实际完成结果及带来源的档案选择。
- `studies/preparation.py`：通过共享 runner 组装 process q 五组、登记固定池 v 四组、单次共享生成三种示例。共享前缀单独登记，不算作任一臂的 H；共享费用归 pair，各臂保留 shared_cost_ref。

准备后快照保留部署与编辑起点，追加公开验证经验和有收据的候选档案，只推进 public_development 游标。验证数据库不修改主分支环境。CandidateBinding 存在准备后快照外，不形成自引用哈希。
