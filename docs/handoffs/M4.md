## RSIHub 阅读与后续设计建议

阅读对象为 [RSIHub: A Composable Framework for Agent-Evolution Methods](https://arxiv.org/abs/2610.32253)，v1 于 2026-10-23 发布，并核对其官方仓库。以下是研究判断，未在 M4 接入 RSIHub，也未执行外部模型实验。

论文将 AHE、Hyperagents、A-Evolve、GEPA 的方法适配放入共同生命周期：select → rollout → analyze → mutate → guardrail → evaluate → absorb。它们是四种方法实例，不是穷尽 RSI 的四类进化方式；论文也将其称为 policy adaptations。统一 recipe 绑定 operator，执行、恢复和谱系由框架提供。见 [论文正文](https://arxiv.org/html/2610.32253v1)。

工程上值得借鉴的是声明可变资源、固定 operator 协议、冻结评价与记录，以及将结果绑定到候选和评价条件。我们的扩展验收也应包含“增加 adapter 无需修改核心 runner/controller”，并在接入前后比较同一个未进化主体的行为，检查框架是否引入额外差异。上述验收建议是本项目的设计判断。见 [RSIHub 设计文档](https://github.com/simple-agent-lab/RSIHub/blob/main/docs/concepts/design.md)。

接入时必须保留语义差异：RSIHub 的 `GateResult` 只有 accept/reject，判断候选的后续父代资格；不能直接充当我们的三值安全准入或真实部署回执。它的 stage 接口也不构成对本项目四个恢复点的能力承诺，每个恢复点都需要实际验证。见 [接口代码](https://github.com/simple-agent-lab/RSIHub/blob/main/src/evolve/frozen/interfaces.py)。

建议把 RSIHub 作为首个外部被测平台，增加 `RSIHubAdapter`，映射候选身份、实际 diff、上下文、测试安排、费用和恢复能力。q 不能直接等同于父代 select；v 应对应可变的内部验证策略，独立效果 oracle 仍留在 Safety Lab。Hyperagents 的 target/operator 共同修改最接近机制更新研究，但第一步可以先用更简单的固定 recipe 验证适配正确性。见 [Hyperagents recipe](https://github.com/simple-agent-lab/RSIHub/blob/main/recipes/hyperagents/README.md)。

论文贡献建议集中于“当前检查通过的机制更新，是否会在后代造成延迟越权，以及有限预算探针能否降低错误接受”。优先完成四族授权电池和独立候选续演标签，再接入真实模型与 RSIHub；覆盖更多 recipe 可以支持迁移结论，不能替代风险标签有效性和对照实验。
