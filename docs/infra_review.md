# 基础设施审阅与整理

日期：2026-11-03。目标是减少真实的重复和扩展耦合，保留研究语义与历史复现。本次没有调用模型、增加任务或修改既有实验结果。

## 第二轮：效率与预算

第二轮针对实际重复工作做了三处局部优化，另外补齐预算预览。没有改变优化提示、公开门槛、探针预算、独立标签或样本数。

| 路径 | 修改 | 保留的检查 |
| --- | --- | --- |
| HTTP网关每次预留预算 | 用同一`BEGIN IMMEDIATE`事务中的SQL聚合读取调用、已用token、未结算预留与超支标志；不再为每次请求解析所有历史响应 | 不使用内存预算计数；其他连接的新预留仍计入。失败、未知与缺失用量仍收费或保留额度；报表仍读取原始provider计价信息 |
| 受限程序的重复执行 | 用精确源码缓存已验证的私有AST，最多64项；无效程序不入缓存 | 每个请求重新创建执行机、复制输入、重置并执行指令预算；工具调用和状态变化仍实际发生，不缓存执行结果 |
| 零售环境重复汇总 | 环境内最多保留256个已通过独立重放的完整记录哈希；相同内容不重复重放 | 每次仍读取文件并校验路径／checksum；变化后的内容必须重新验证。新实例／分支重新验证，额外核对source与guard绑定 |
| 运行前成本判断 | `platform validate`显示单次运行的额度；新增`platform pilot-validate`显示根、四臂、重复和审计方法对应的累计额度 | 只读、无需密钥、不创建模型日志；不改变正式运行的分配规则，不把额度说成预计账单 |

相同脚本、相同输入、每版本7次本地测量的中位数如下。全部输出哈希一致；这是CPU与本地IO微基准，不包含网络等待，不代表整场试验或API费用下降相同比例。

| 场景 | 修改前 | 修改后 | 可确认的收益 |
| --- | ---: | ---: | --- |
| 300个零售请求的真实受限程序执行 | 224.3 ms | 147.3 ms | 耗时下降34%；语法解析320→1次，仍执行300个请求 |
| 500条合成模型历史后，预留10次调用额度 | 377.5 ms | 10.4 ms | 该预算路径约36倍加速；历史响应解析5045→0次 |
| 50条合成历史后的相同预留 | 46.7 ms | 9.0 ms | 较小日志也有收益，约5倍 |
| 5条零售执行及10轮完整汇总 | 280.9 ms | 260.4 ms | 耗时下降约7%；重放265→5次，磁盘读取和规范化仍占主要开销 |

零售计时收益较小，不把重放次数降低98%说成整体提速98%。缓存只避免相同不可变内容的重复计算；不跨根或重复合并模型请求，不复用独立标签，不取消OpenEvolve在当前公开任务上的档案重评分。

基准入口：`python scripts/benchmark_infra.py --samples 7 --output <新JSON路径>`，也可用`PYTHONPATH`指向冻结源码进行前后比较。原始计时、工作量计数、输出哈希、修改前源码及最终验证位于`runs/infra-efficiency-20261103`。合成模型历史由本地夹具构建，传输调用为0；测得的预算收益不是远程推理加速。

### 真正控制API支出

四臂pilot目前按每根提案、每条件/臂/重复、每探针方法分别分配模型预算。预览命令把这层乘法显式展示：

```bash
rsi-lab platform pilot-validate --config configs/platform_workflow_kimi.toml --roots 2 --audit-baselines
```

当前配置下这会展示14组网关、累计17,248次HTTP调用额度及63,000,000配置token额度；不是预计用量。默认网关的scripted角色不计付费调用。自定义工厂的外部调用不受此预览覆盖，OpenEvolve专用筛查的50次全局调用上限也不按此方式展开。

已有持久化响应恢复和未知调用不重发继续保留。下一次真实运行应先依据这份预览收紧根数、重复数和角色额度，再登记协议；不能在看见独立结果后随意更改预算。提示压缩、换模型、减少检查和模型响应跨重复缓存都可能改变实验条件，本轮没有把这些作为透明infra优化。

### 灵活度复核

| 扩展对象 | 当前可复用部分 | 仍需显式实现的部分 |
| --- | --- | --- |
| 新的提示词或受限程序优化器 | 命名版本组件、快照、候选、公共评价、分支、准入与恢复；第三方registry测试已有覆盖 | 上游版本锁、完整继承状态、原生选择边界与额外平台门槛的记录 |
| 新业务任务与oracle | 任务拥有自己的round数据、工具协议、公开轨迹与评分hook；内核不导入具体世界 | 真实效果判定、公开/探针/独立划分；顶层schedule仍是有限配置清单 |
| 新模型服务或多模型角色 | actor/editor可分别配置兼容HTTP服务；特殊网关可注入可信工厂 | 超过两种角色、自定义传输和额外内部调用的预算/来源记录；没有任意自动插件发现 |
| 新审计方法 | `AuditView`、探针能力、报告和准入端口，以及既有训练契约 | 当前CLI方法清单仍固定，新方法需要显式装配与配置验收 |
| 任意Python/harness自修改、远端或并发优化器 | 版本和候选记录可以沿用 | 已验收的OS隔离、远端提交一致性及并发恢复；现有OpenEvolve和scripted实例不可直接共享到线程池 |

因此，目前框架适合继续接入能在提交前暂停、完整快照并通过既有工具执行的系统。暂不为“可能用到”扩大插件机制；先针对下一套真实系统补缺口。当前最大的通用性限制是执行与恢复能力，而不是必须把受测系统强行拆成q/v。

## 判断

公共`SystemAdapter`、`TaskPackage`、候选绑定、分支、续演与激活边界可以继续复用，适合接入支持快照和提交前暂停的外部系统。主要维护成本来自历史实验入口多、公共辅助代码位置不合理及模型装配仍偏向内置系统；不需要重建平台。

可扩展性还不能等同于开箱即用的任意RSI执行：第三方插件需要可信Python装配，任意生成代码的OS隔离、远端一致性、全交互任务及完整原生行为仍需各自实现和验收。

## 已处理的问题

| 问题与影响 | 整理结果 | 验证要点 |
| --- | --- | --- |
| 新系统已注册，默认scripted模型却可能落到Task A控制响应，产生错误的“已接入”轨迹 | registry可登记专属`ScriptedModel`；缺失时明确失败；单次实验与pilot均传递同一registry | 外部示例插件真实走准备、续演、准入与恢复；缺失控制不创建模型日志 |
| 工厂实际系统与预检描述未核对，可能绕过声明的兼容性 | 构建后比较实际descriptor与声明 | 不一致时在提案前失败 |
| OpenEvolve、q和其他研究从fixture导入组件操作，OpenEvolve从q模块借用门槛；零售从授权任务类借用评分 | 组件操作移到`api.versions`，规范JSON留在serialization；成本门槛和目标分别放在明确的共享模块 | 旧导入别名保留，合法输入字节和评分不变；新模块不依赖fixture或q研究 |
| 组件名写错时`replace_component`静默返回无变化版本 | 明确拒绝不存在的组件 | 保留角色、顺序及revision；缺失组件失败 |
| OpenEvolve需要`evaluator.plan`，公共端口却没有声明 | 增加可选`PlannedPublicEvaluator`，缺失时提前报能力错误 | 不执行公开评价或请求模型 |
| 本地系统、授权世界、激活控制器有三份相同SQLite写事务 | 提取`infra.sqlite.durable_transaction` | 保留FULL同步、IMMEDIATE事务、回滚／关闭及sidecar路径检查；模型journal事务不合并 |
| 顶层CLI分发和帮助维护两份清单，OpenEvolve已能运行却没有帮助条目 | 单一显式路由表；旧阶段命令留在兼容模块，新命令按需加载 | 所有路由出现在help，新入口不加载旧runner；旧命令与退出码继续测试 |
| README积累了大量具体历史实验说明，部分系统／任务清单过时 | README缩成安装与入口，完整命令移到`docs/experiments.md`；新增扩展指南 | 更新本地文档链接；不删除历史命令、配置或实验工件 |

## 保留的边界与后续条件

- `studies/`占源码较大部分，其中很多是不同预登记协议、干预与统计定义。相似的循环不一定等价，不为减少行数合并研究含义不同的试验。
- 旧P0的`contracts.py`、`ports.py`、阶段命令和golden测试仍支撑冻结复现；公共扩展使用`api/`。旧文件有使用者，因此未按文件年龄删除。
- 数据库模型journal控制请求前后的事务，与本地状态写事务不同，未作泛化合并。状态完整性检查也没有为了速度移除。
- 当前第三方装配需要显式Python注册；没有自动加载任意配置中的代码。若接入量增加，再评估受控插件发现与包分发。
- 有些专用研究仍直接使用具体任务和内部分析函数；它们是实验组装，尚未承诺为稳定第三方API。外部作者应先使用扩展指南，不依赖所有研究脚本的私有函数。
- GEPA的模型／任务组合校验仍有内置配置约束。只有出现第二种需要同类跨配置校验的插件时，再抽取通用校验hook，避免提前建立复杂插件框架。
- 上游完整行为、额外公开门槛和外部防御的研究分离仍按[覆盖表](openevolve_coverage.md)处理；本轮结构整理没有改变它们的含义。
