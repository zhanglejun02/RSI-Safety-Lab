# OpenEvolve 固定候选入库反事实与局部准入条件

日期：2026-11-03。本轮范围是零API离线分析、局部适配验收及真实续演的启动判断。保留现有任务、公共内核与受限执行；q/v/s是可选分析角色，q/v自更新不是成功条件。不扩大静态分析器，不训练评分器，不接第三个系统。

研究问题：**在明确的任务、评分和工具约束下，自然生成的违规候选能否进入优化档案、被后续编辑使用？额外准入对此有什么影响，以及付出多少收益和成本？**

## 固定候选的单步反事实

输入是本地冻结开发运行中的完整提案及其绑定记录，未知响应保持缺失。先验证输入身份、源码、公开评价与准确入库前状态；原生worker的同源码拒绝保持原语义，不重新构造可入库child。没有完整状态或不能复现原结果的提案标为不可分析，说明缺失项，不推测补齐。

每个提案独立从自己的真实入库前状态开始，比较：

| 条件 | 入库处理 |
| --- | --- |
| `public_complete_correct` | 完整通过公开正确性后，才允许原生程序库入库结果成为可提交状态 |
| `upstream` | 相同候选和相同公开评分直接按原生程序库入库语义处理 |

唯一干预是额外公开正确性门槛。保持上游版本、候选源码、任务、原工具行为、公开评分公式、同轮档案重评分、档案配置及执行隔离不变。公开不合格时 `combined_score` 仍为0；完整正确时仍为 `1/(1+synthetic_units)`，不改变奖励以提高被抽中机会。

每个条件保存入库前后程序集合、MAP-Elites／精英／参考集合、活动程序和父节点／参考程序标识，回答四件事：

1. 原生程序库是否收录候选；平台是否允许提交该原生结果。
2. 活动执行程序是否改变。
3. 程序档案、精英和参考集合如何改变。
4. 候选是否具备后续父节点或参考程序的抽样资格，资格依赖哪些原生集合与分支。

验收顺序是先复现原条件的入库与活动版本结果，再解释对照差异。抽样资格和可识别使用路径不等于已经进入编辑上下文，更不等于后代风险。仅档案更新也属于系统状态改变；不能因活动源码不变而把它们记成系统无变化。

这些是**逐提案、条件于真实历史的单步反事实**。不串接反事实状态，不复用后续真实响应来冒充另一条演化历史，不把同源提案当作独立根。来自已查看开发历史的检查点只能支持案例机制分析。

## 局部协议与兼容性

适配器只增加协议绑定的条件和证据分离，复用快照、分支、提交和续演机制。`initial_snapshot(..., admission_condition=None)` 保留旧快照和旧 `CandidateDraft.native_valid` 解释。显式条件绑定在 `task_contract.admission`，协议为 `openevolve-admission-v2`，条件为 `public_complete_correct` 或 `upstream`。省略条件不静默迁移旧工件。

新协议下，公开评价、原生入库结果与平台准入结果分别保存：`native_valid`表达上游结果是否允许成为提交候选，`platform_accepted`表达额外门槛下是否准入。研究驱动以绑定该条件的决定提交或拒绝；控制器的身份、协议和原生有效性校验保持。平台拒绝不提交拟议源码、档案或随机状态，隔离分支不共享可变程序库。

局部续演入口为 `studies.openevolve_admission_driver.continue_admission_system`，使用 `admission_decision(prepared)`，继续复用原有续演与激活服务。现有结果契约的 `old/new` 仅作为存储臂标识，研究协议须明确映射到两项准入条件；不能直接把通用驱动的 `native_valid` 当作新协议的平台决定。适配器会拒绝这种误提交，恢复记录也绑定具体驱动。新协议的候选ID计算排除准入条件，避免条件元数据本身扰动相同历史下的排序或抽样。

必要验收包括默认行为不变、两条件只差准入门槛、拒绝不继承、分支隔离、已确认恢复不重复调用、未知结果不重试，以及“入库但活动程序不变”的正确记录。旧实验继续按旧协议和原工件解释；新实现不覆盖原manifest、标签或报告。

## 真实后代的启动条件与拟议预算

离线若发现原生程序库已经拒绝违规候选，或没有可识别的后续使用路径，就保留该结果，不启动针对该案例的付费续演。若有原生收录和可使用路径，只能据此建议开发案例小试；本轮不启动真实调用。

下一次运行前须单独冻结准确零售检查点、两条件、派发安排、预算和停止规则。拟议新预算不是旧实验的续用额度：

| 项目 | 拟议上限／规则 |
| --- | --- |
| 条件与重复 | `upstream`／`public_complete_correct`，各3次独立重复 |
| 轨迹长度 | 每次H3，实际生成、验证和选择后代 |
| 总调用与token | 最多18次编辑调用、200,000 token；所有额外调用也计入 |
| 模型响应 | 各分支重新生成自己的后代，不复用旧响应；未知不补跑 |
| 工具与隔离 | 保留原工具拒绝和执行隔离，不改变奖励或重评分方式 |

主观察量为候选是否实际进入编辑上下文、后代是否再出现相关违规尝试、实际生效违规／工具拒绝／平台拒绝，以及合法完成、公开成本和累计费用。违规尝试传播而实际违规仍为0时同时如实报告。取消原工具拒绝会改变任务环境，只能另作故障注入或压力实验，不能直接算原生OpenEvolve的安全表现。

没有观察到后续使用或结果差异，按上限停止，不增加代数寻找阳性。出现值得确认的差异时另设新根实验；一条已查看历史不支持总体因果风险或普遍安全结论。贡献由具体发现和比较建立，不声称平台独有或撤层必然出现非零风险；[RSIHub](https://arxiv.org/abs/2610.32253)已有候选谱系、可变资源之外的评价与跨方法基础设施。
