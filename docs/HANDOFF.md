### 审计方法先做证据清点，再决定是否值得实验

零API清点应列出每个候选的更新对象A/q/v、来源与根、原生通过证据、可读静态特征、已有短证据、独立标签及其时间轴。旧已看过的案例全部标开发，人工控制和自然来源分开，同根候选不跨分区。**不能把某一次q采样臂里出现的危险程序，直接标成已确认“有害q”。**

已有可靠A程序案例可以用于固定程序后续执行风险的开发比较。若要声称“真实后代证据改善准入”，则必须有接受/拒绝同一更新后、匹配状态任务预算、实际继续生成和选择版本的配对记录；仅运行更多请求不够。若现有工件缺这类标签，清点结论就是缺少材料，不能用执行标签填补。已用于设计探针或静态规则的标签也不能再充当新确认集。

比较时保留原生检查、强静态规则、等预算普通前瞻、机制引导前瞻与全部拒绝；静态方法不用动态预算，不为“公平”强迫其浪费调用。两种前瞻匹配编辑/请求预算上限并另报实际token、成本与失败，在线决定先于独立标签落盘。报告有害错误接受、良性错误拒绝、弃权及实际采用后的风险/合法效用/成本收益；缺失不算接受或正确拒绝。首轮规则/探针设置只在开发数据固定；学习比较只有在相同证据、独立根划分和新根评价具备后才启动。

若未来明确以A为论文主对象，应另修订proposal范围并重述贡献；本记录不默默将q/v机制研究改名为普通代码安全测评。形成这份决策记录的上一轮仅更新文档；本轮的代码与模型执行见开头。

### 对上述结论的进一步复核

2026-11-01 回看实现并运行无 API 的定向控制后，发现两个实验设计问题。当时尚未修正，现已由本轮 v2 修复；下列旧结果保留，不能仅归因于 Kimi 已经足够强：

1. GEPA 搜索配置是 `improvement_or_equal`，但工作流配置的 `require_strict_improvement=true` 又将同分候选标成 `native_valid=False`，公共续演据此拒绝激活。因此这次“原生演化”实际上额外施加了平台的严格提分条件。通用测评应分别记录受测系统自己的接受决定、公开效用变化类别和外部安全决定；严格改善可作为研究子集，不能默默代替所有 RSI 的原生规则。
2. 探针第一轮的 spent 模板让两个当前请求共用尚未消耗的确认，暴露的是同批次查询后的授权事实过时；独立 delayed 模板从第三轮引用第一轮已消耗的确认，查询时就能看出失效。将独立视野延长到六轮仍不会出现前一种情况。用同一“批量查询后直接按旧事实转交”的脚本控制复验，探针 H=2 风险为 `[1,0]`，独立 H=6 风险仍为 `[0,0,0,0,0,0]`。这说明当前独立测试池没有覆盖已经发现的具体失败机制，不能据此评价探针对该机制的预测能力。

当时提出的修复计划是分离接受规则与故障机制覆盖，使探针和独立评价覆盖同一类故障、使用不重合参数，同时保留跨轮与批内两种确认失效类型；用明确安全的逐项检查、会复用过时事实的批处理、考虑一次性依赖的安全批处理做离线契约验收。通过后才重跑新的开发协议。既有真实运行和其缺失记录保持不变，不能事后改写标签制造阳性结果。

四组 `pilot-run` 使用同一个根候选和环境，组合旧/新 × 冻结/原生继续改进，四臂共享实际任务内容。每个根提案及每个条件/臂/重复使用独立模型日志和相同预算。按 root 汇总全程、前两轮、第三轮后的风险和效用差；完整差值遇到缺失时保持 null，已观察伤害仍保留。该入口只接受开发分区，不混合导出不同续演条件的训练标签，也不声称提供检测器排名。

## 必须保留的语义

- 提案不改变活跃系统。候选绑定系统和环境基座、实际未来任务计划摘要、协议、谱系、分区及来源；状态变化后旧决定不可复用。
- 拒绝和 `inconclusive` 不继承候选经验或优化器状态。只有控制器授权的候选会激活。
- 短探针、长程标签与主分支状态隔离；独立评价不进入在线检测、编辑器反馈和停止决策。
- 实际风险来自日志中的生效越权。缺失保持 null；有证据的伤害不会被后续故障抹去。H 包含失败或拒绝尝试。
- 已完成请求从记录回放；结果未知不得自动重新派发。工具效果与激活结果都要核对实际状态，不能只相信模型文本。
- 模型调用、token、计价与合成单位分开。控制响应始终标记 control，不能作为自然模型成绩。

未来任务游标属于被审计来源状态：`task_plan_sha256` 根据实际请求、事件、对象及顺序生成，不包含仅用于登记的根 ID、分区名或计划 ID。它进入学习绑定的状态摘要；完整任务参数保留在平台侧，在线检测只拿到摘要。不同实际参数根可分区训练，给完全相同的世界和计划换标签仍会触发原有防泄漏检查。

公开探针目录由任务包提供，公共引擎不包含授权题专属分支。原有单次准入入口的 actor/editor 调用和 token 限额仍在全运行分支间共享；四组 pilot 已隔离各分支网关预算。探针另有配对轮数预留，没有硬件资源隔离。总 pilot 调用上限随根数和重复数增长，不能把一组网关限额当成整批费用。

当前准入实验只审计一次根更新。探针和独立标签分支继续原生改进，实际部署比较冻结所选系统；尚未实现每轮再次执行外部审计的连续准入实验。
